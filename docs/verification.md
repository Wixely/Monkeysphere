Building current main with the migration sources converted to CRLF reproduces the fixture's stored checksums exactly (v1 246563bc, v2 ddc4b39f, v3 f61d4f27), proving line endings are the sole cause and that the migration text is unchanged. The affected checksums are therefore computable exactly, so a deterministic repair is possible without a DnaX change. The restore path and backup format are not at fault. Both published alpha ZIPs are affected, established by reading the migration SQL out of the Monkeysphere.Data.dll inside each downloaded release asset: v0.1.0-alpha.2 (commit 30e8bea) contains CRLF in both win-x64 and linux-x64, which are built by the same windows-latest job.
